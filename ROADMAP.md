# Roadmap

Over the next twelve months the project plans to preserve safe backup/restore and exact-version approval behavior, improve reproducible deployment documentation and test additional interruption and storage-failure scenarios. Release changes must retain synthetic tests and clear installation acceptance boundaries.

Security priorities are an end-to-end qualified deployment with protected HA, MQTT, Kubernetes, registry and storage transports; exact dependency/toolchain evidence; and continued review of privileged archive and update operations. A transport test or an offline restore component does not qualify the complete networked system.

Maintenance priorities are a backup maintainer and one-week access recovery mechanism, broader documented compatibility evidence, and periodic reproducible fuzzing of each release candidate. Dates are planning targets, not promises of unperformed tests or completed certification.
